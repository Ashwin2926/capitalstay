Capital Stay UX audit

A review of every page type on the site at phone (390px) and desktop (1400px) widths, covering usability, accessibility (WCAG 2.1 AA), speed, content and visual consistency. Findings are ranked by how much they cost guests and owners today.

Fix now

Problems guests or owners hit on every visit, or that break trust.

  1. 01
    P1 · speedAll pages

    A full-screen loader hides every page for up to 2.5 seconds

    The app waits for all four home slideshow photos (about 3.6 MB) before showing anything, even on pages that never use them, such as Team or a location page. On mobile data most visitors see the loader for the full 2.5 seconds, and some leave.

    Remove the global loader. Render the page immediately and load only the first hero photo up front on the home page; fetch the rest after the page is visible.

  2. 02
    P1 · speedServices, Management, Home

    Images are far larger than they are displayed

    Guest Services and Property Management each download about 7 MB of images on first view. The worst files are listed below. A hero needs about 1,920px wide at roughly 250 KB; a card needs about 800px at under 100 KB.

    FileSizeUsed on
    services/Owner_bg.png2,662 KBProperty Management
    data/businessbay.jpg2,235 KBLocation pages
    services/guest_services_banner.webp1,767 KBGuest Services
    background5.webp1,643 KBHero
    background.webp1,574 KBHome hero (loaded on every page)
    services/maid.webp1,047 KBGuest Services

    Re-export images at display size (WebP or AVIF, quality 75–80), add srcset so phones get smaller versions, and keep loading="lazy" for everything below the first screen.

  3. 03
    P1 · trustFooter, News

    Placeholder content is live

    The Facebook, LinkedIn and TikTok icons in the footer open those sites' home pages, not Capital Stay's profiles. News cards link to # and use stock Unsplash photos, and “Subscribe to Newsletter” opens example.com. Visitors who click any of these conclude the site is unfinished.

    Add the real profile URLs or remove those icons. Give each news story a real page or remove the “View Details” link, use your own photos, and connect or remove the newsletter button. Check that every award and figure on the News page is accurate before it stays public.

  4. 04
    P1 · usabilityHome search

    The Hotels / Villas / Apartments filter does nothing

    The selected type is never added to the booking search link, so guests who pick “Villas” still see every property type.

    Pass the type to the Hostaway search if the booking engine supports a type filter; otherwise remove the control.

  5. 05
    P1 · accessibilityFooter, all pages

    Footer links can't be reached by keyboard or opened in a new tab

    The footer links are clickable list items, not real links. Keyboard and screen-reader users skip them entirely, nobody can open them in a new tab, and search engines don't follow them.

    Replace each one with a router <Link>, or an <a> for external pages.

  6. 06
    P1 · accessibilityAll pages, listing form

    Unnamed controls and unlinked form labels

    Screen readers announce the back-to-top button, the six social icons and the payment logos with no name (axe: button-name, link-name, svg-img-alt). In the “List your property” form the labels aren't connected to their fields, so fields are read without names and tapping a label doesn't focus its field.

    Add aria-labels (for example “Back to top”, “Capital Stay on Instagram”) and give each form label an htmlFor that matches its input's id.

Fix next

Real issues with a smaller or less frequent impact.

  1. 07
    P2 · accessibilitySeveral pages

    Low-contrast text

    These fail the 4.5:1 minimum: the cookie banner's Accept (2.8:1, white on green) and Decline (3.7:1) buttons, the footer copyright line (2.8:1), the News category labels (gold “Award” is 1.4:1, green 2.3:1, orange 2.8:1) and “Verified Airbnb Host Since 2020” (2.5:1). Links inside FAQ answers are distinguished by colour alone. Some faint text on Property Management was caught mid-fade-in by the scanner and is fine at rest.

    Darken those colours to at least 4.5:1 and underline links that sit inside paragraphs.

  2. 08
    P2 · usabilityAll pages, phones

    The cookie banner takes over the first screen on phones

    Its text alone is 176px tall, and Decline is styled as a red warning button, which reads as an error and pressures visitors to accept.

    Shorten the copy to one or two lines with a “Learn more” link, keep the banner under about 120px, and give both choices equal visual weight.

  3. 09
    P2 · accessibilityNavigation

    Desktop menu uses the wrong ARIA pattern

    The menu is marked as an application-style menubar but contains plain list items, which axe rates critical (aria-required-children, listitem). Screen readers announce it inconsistently.

    Use a plain <nav><ul> of links, with a disclosure button (aria-expanded) for each dropdown.

  4. 10
    P2 · speedAll pages

    Every page downloads the code for every other page

    The site ships as one 883 KB JavaScript file (243 KB compressed).

    Lazy-load each route with React.lazy so each page loads only its own code.

  5. 11
    P2 · SEO riskSite-wide structured data

    Hard-coded review rating in the search markup

    The site tells Google it has a 4.9 rating from 120 reviews in its own markup. Google's rules don't allow businesses to mark up reviews about themselves on their own site, and violations can lead to a manual penalty.

    Remove aggregateRating from the organisation schema, or replace it with an approved review widget's markup.

  6. 12
    P2 · usabilityRouting

    No real “page not found” page

    Any one-word address, for example a typo like /servcies, shows only “Location not found.” with no way forward.

    Show a branded not-found page with search and links to the main locations and home.

  7. 13
    P2 · accessibilityPage structure

    Missing main region and skipped heading levels

    Five page types have no <main> region, Guest Services has two site headers, and some headings skip levels (for example amenity titles are h6 directly under an h2). Screen-reader users rely on these to jump around a page.

    Wrap page content in <main>, keep a single site header, and step headings down one level at a time.

Polish

Consistency work that makes the brand feel more premium.

  1. 14
    P3 · visualManagement, Furnishing, Location

    Two competing heading styles

    The home page and hero use the elegant Cormorant serif, while Property Management, Furnishing and the location pages switch to heavy black sans-serif headings. The site feels like two brands.

    Use Cormorant for page and section headings everywhere and the sans-serif at semibold for card titles.

  2. 15
    P3 · visualSite-wide

    Buttons and card corners vary page to page

    Buttons come in at least four styles (blue pill, navy rounded, white outline, uppercase versus sentence case), and card corners range from 14px to 40px.

    Define one primary and one secondary button and two corner sizes, then reuse them everywhere.

  3. 16
    P3 · code healthDevelopers

    Shared class names can clash

    Several components inject global CSS with generic class names (.content-wrapper, .title, .icon), which can override each other when two of those components appear on the same page. There's also an existing lint error in Services.tsx, plus unused files (old.jsx, back.jsx).

    Move component styles to Tailwind classes or CSS modules, fix the lint error, and delete the unused files.

  4. 17
    P3 · usabilityHome search, Key Destinations

    Booking opens in a new tab

    Search and destination cards open the booking site in a new tab, so on phones guests end up with several tabs open and lose track of capitalstayuae.com.

    Open the booking site in the same tab for now; the planned Hostaway integration (in docs/TODO.md) keeps guests on your own site until payment.

Suggested order

  1. One session, code only: remove the global loader (01), real footer links and labels (05, 06), contrast fixes (07), menu pattern (09), route lazy-loading (10), schema rating (11), 404 page (12) and main regions (13).
  2. Image pass: re-export and resize the heavy images (02). This alone should cut first-view downloads by more than half.
  3. Needs your input: real social profile URLs, news stories and photos, the newsletter tool, and a decision on the property-type filter (03, 04).
  4. Design consistency: heading, button and corner standards (14, 15), applied page by page.

Limits of this audit

Tested in Chromium on a local production build; the live site, real phones and Safari were not tested. Google Maps, the booking site and stock photos were blocked in the test environment, so those areas were not reviewed visually. Load sizes were measured, but timings on real mobile networks were not.
